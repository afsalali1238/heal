## The seven non-negotiables

These are unchanged by the merge. They apply to every file and every tool.

1. **Content lives in the Google Sheet, not in the repo.** `anatomy-explorer/src/data/areas.json`
   and `items.json` are generated by `npm run sync:content`. Hand-editing them puts the repo out
   of step with the sheet and the next sync silently reverts you. **A content change is a sheet
   change.** The sheet contract is `anatomy-explorer/docs/CONTENT-SCHEMA.md`.

2. **Never invent clinical content.** Exercise names, instructions, dosages, target muscles and
   safety lines come from the physiotherapist. Anything clinical you add ships as `status: draft`
   with empty `reviewed_by` and `reviewed_date`. **Never write a clinician's name or a review
   date.** If something looks clinically wrong, **flag it — do not fix it.** The render gate
   enforces this: an item is shown to patients only when it is `published` **and** carries a
   non-empty `reviewed_by` **and** its image is approved. That gate is the product's core safety
   guarantee; do not route around it.

3. **Never relax the compliance check.** `anatomy-explorer/src/lib/compliance.ts` holds **53
   word-boundary rules** — 8 superlatives, 4 outcome claims, 5 booking CTAs and 36 condition
   names — enforcing the DHA advertising standards, the MOHAP booking-CTA rule and the
   no-condition-names rule. A build that goes green because a rule was loosened has removed the
   product's core legal constraint, silently and invisibly. **Fix the content, never the check.**
   (Import this module; never re-implement it — a naive substring copy exists in
   `scripts/sync-content.ts` and is a known defect, not a pattern to follow.)

4. **Do not touch config or lockfiles as a side effect.** `astro.config.mjs`, `package.json`,
   `package-lock.json`, `tsconfig.json`, `.github/`. An agent once deleted `astro.config.mjs`
   while working on something else and nobody noticed for days — that is how the Vercel adapter
   and the sitemap went missing. If your task genuinely needs a config change, **say so and stop.**

5. **Navigation is by body area, never by condition.** Decision D-001, and it is the clinician's
   own call. No diagnosis language anywhere — including comments, identifiers, filenames and
   commit messages.

6. **No analytics, accounts, tracking or backend.** Decision D-007. This is why the Vercel
   `webAnalytics` flag is not coming back (`astro.config.mjs` correctly has it off). Three
   `localStorage` keys are permitted (last chosen area, text size, device-local
   completion marks) and nothing else. The completion list never leaves the
   device — there is no backend to send it to.

7. **17px base font. Areas sort head to toe, never alphabetically.** Decision D-014.

### Enduring cautions (lessons that outlived the deleted files)

- **Never hand-author clinical content in a script.** The deleted `add-lowerback.js` did exactly
  that (dosages and safety lines in code) and was the source of a `lower-back`/`lowerback`
  image-id mismatch. If you find that pattern reintroduced anywhere, it violates non-negotiable #2.
- **Never restore `webAnalytics` or a placeholder `site`.** An old committed `astro.config.mjs`
  carried `webAnalytics: { enabled: true }` and `site: 'https://example.com'` — a direct D-007
  violation. The current config is correct; do not "helpfully" revert it.
- **Do not wire an unversioned, cache-first service worker.** A dead `sw.js` with no versioned
  invalidation would serve a retired exercise indefinitely. Offline support, if built, needs
  versioned invalidation.

## Two environment notes

**Git writes fail over the Claude device bridge.** `.git/index.lock` is not writable on the
mount. Run every git command — including commits and pushes — from a real terminal.

**Builds cannot run over the bridge either.** `node_modules` holds Windows native bindings and
the bridge shell is Linux, so `build`, `lint` and `typecheck` all fail there for reasons that
have nothing to do with the code. **Say so honestly rather than reporting a check as passed.**
(The host Node is now v22.23.2, which satisfies the `>=22.12` requirement, so earlier
Node-24-specific gate crashes appear historical — but this is unverifiable over the bridge.)
